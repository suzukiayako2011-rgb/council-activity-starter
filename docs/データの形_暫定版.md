# データの形（暫定版 starter-0.1）

各自が同じ項目名・値の形で記録し、後で機械変換しやすくするための学習・交換用仕様です。三神DBの正式schemaそのものではありません。

[架空の見本JSON](../examples/starter-0.1.json)と[JSON Schema](../examples/starter-0.1.schema.json)をAIに渡してください。見本は実在議員のカードの言い換えではなく、町・会議・内容をすべて架空にした例です。公式資料が存在しないため `source_url` と `follow_up` は `null` です。

## ファイルとID

- ファイル全体に `schema_version: "starter-0.1"` を1つ置き、カードには繰り返しません。
- `dataset.slug` は半角小文字・数字・ハイフンで一度決め、以後変更しません（例：`your-slug`）。
- `records` にカードを並べます。`id` は `your-slug-000001` の形で6桁の通し番号を付けます。IDは日付・重要度・表示順から作らず、並べ替えても変えず、削除した番号を再利用しません。
- 同じファイル内でIDを重複させず、接頭辞を `dataset.slug` と一致させます。この2点はJSON Schemaだけでは検査できないため別途確認します。

## 1件の単位と空欄

1件＝1つの論点。1つの求めと、それに対応する答弁を基本単位にし、複数論点は原則分けます。予算要望は、要望書上の1項目を1件とします。

項目名は下表に揃え、**分からない・未判定・該当しない項目は `null`** に統一します。空文字 `""` や「不明」「未判定」を値にしません。IDは必ず付けます。情報が未確認のカードは作業用として保存できても、そのまま公開してよい意味ではありません。公開前に内容と出典を人が確認してください。

| 項目 | 書く内容・値の形 |
|---|---|
| `id` | 恒久ID（必須・null不可） |
| `date` | 質問・提案を行った日：YYYY-MM-DD。推測しない |
| `meeting_type` | 本会議／委員会／特別委員会／予算提案 |
| `committee` | 委員会名。本会議など該当しない場合はnull |
| `session_name` | 会議名・会期名 |
| `question_topic` | 1つの論点の短い題名 |
| `issue` | 取り上げた課題・問題意識 |
| `proposal` | 具体的な提案・要求。確認を求める質問もここに記録 |
| `answer_summary` | その求めに対応する行政の答弁・回答の要旨 |
| `result_level` | 下記6区分のいずれか。迷う場合はnull |
| `tags` | 共通15分類の文字列配列。未分類はnull、分類できたら1つ以上 |
| `local_tags` | 自治体・議員固有の自由タグの文字列配列。未確認はnull、付けないと決めた場合は空配列 |
| `source_type` | 議事録／予算提案 |
| `source_url` | 確認した公式出典のhttp/https URL。まだ分からない場合はnull |
| `follow_up` | 暫定・将来変換対象。下記の1行メモまたはnull。正式確定した中核項目ではありません |

項目名の互換性は現行三神DBを優先しています。ただし、ファイルの包み方・null許容・`local_tags` はスターター独自です。現行DBのschemaへ直接投入する形式ではありません。値の型を変えたり独自項目を追加したりせず、自由な分類は `local_tags` に書きます。

## 対応状況の6区分

未判定は `null`。第7区分「未判定」は追加しません。当時の答弁・回答に基づいて判定し、後年の実現だけで上書きしません。

以下は公開共有ファイル所収 `D-20260928-JISSHI-DEFINITION` §2・§3の本文をそのまま転記しています。

**実施済**:答弁・回答の時点で、提案の対象がすでに実際に開始(実施)されていると、
当時の資料で確認できるもの。

「実施済」に含めないもの:

- 実施の約束、開始年度の明示(「〜年度から開始」)
- 予算措置(予算措置は、実施の証明にならない)
- 議案・条例の可決(決定であって、実施ではない)
- 後年に判明した実現(`follow_up` に記録する。判定には使わない)

区分名「実施済」は維持する。6区分の構成は変えない。

## 3. 隣接区分との境界

| 区分 | 使うとき | 現行READMEとの関係 |
|---|---|---|
| 実施済 | 提案の対象が、答弁時点ですでに実施されている | **変更**:実施の約束・開始予定・後年の確認を含めない |
| 改善・対応予定 | 具体的な対応(内容・時期・事業)が示されたが、実現は確認できない。実施の約束、開始年度、予算計上を含む | 定義は維持。旧「実施済」の一部がここへ移る |
| 検討を引き出した | 「検討する」と明言。内容・時期なし | 変更なし |
| 研究段階 | 「研究する」「動向を注視」 | 変更なし |
| 提案のみ | 提案に直接応じない、既存の取組の継続を述べるだけ、実施しない | 変更なし。適用は§4の原則3による |
| 適正確認 | 質問の目的が、行政の判断・手続き・条例の文言の適正の確認 | 変更なし |


### 判定の原則（運用部分をスターター向けに一般化）

以下は同decision §4です。「確定は三神が行う」「分割の要否を三神が判断する」の担当者だけを、データを公開する議員本人へ一般化しています。

1. **文言だけで自動判定しない。** 提案の対象の全部が実施されているのか、一部なのかは、
   当時の答弁・回答の原文と、質問・提案の範囲を照合して判断する。
   AIは候補の提示まで。確定はデータを公開する議員本人が行う。
2. **全部か一部か。** 提案の対象の一部だけが実施済の場合、「実施済」にしない。
   未充足の部分についての答弁で区分を決める。
   複数の論点が1件に混在するカードは、分割の要否をデータを公開する議員本人が判断する。
3. **「提案のみ」は、提案の範囲ごとに判断する。** 既存事業の存在だけでは、
   「実施済」にしない。質問が求めた部分(拡充等)に答弁が応じていない場合は、
   その部分について区分を決める。
4. **予算措置は、実施の証明にしない。** 予算計上は「改善・対応予定」。
5. **後年の情報は、判定に使わない。** `follow_up` に分けて記録する。


三神たかしの公開DB／サイトは新しい「実施済」基準への移行監査中で、既存値・表示には旧基準が残っています。見本サイトの旧表示を、新規データの判定基準としてコピーしないでください。

## 共通分類と自由タグ

`tags` の共通15分類は次のとおりです。表記を変えたり追加したりしません。

- DX
- まちづくり
- スポーツ
- 人権・多様性
- 保健衛生・医療
- 子ども・子育て
- 市民活動
- 教育
- 文化芸術
- 環境
- 社会福祉
- 経済・雇用
- 行政運営
- 議会改革
- 防災・消防

自治体・議員固有の呼称（例：資料館）は `local_tags` に分けます。

## 「その後の市の動き」の暫定メモ

置き場所は `follow_up` に統一します。中核の正式確定項目ではなく、**暫定・将来変換対象**です。未調査・未確認・出典不足の場合は `null`。nullは「動きがない」という断定ではありません。

人が資料の内容を確かめた場合だけ、次の形の1行にします。

```text
（確認した事実）。（出典：URL、YYYY年MM月DD日確認）
```

最初の括弧は説明用です。実際には、確認した事実の文を書き、末尾に「。（出典：…、…確認）」を付けます。URLは公開資料の出典、確認日は記述を支える内容を人が確認した日です。

提案との因果を主張せず、「成果」「実現させた」と書きません。出典のない断定、質問の対象と無関係な動きも載せません。[READMEの表現ルール](../README.md#はじめる前に必ず確認すること)と、共有ファイル所収 `D-20261002-CAUSAL-WORDING-SCOPE` に従います。

将来の構造は未確定です。内部の構造化案はproposedであり、本書で正式な構造や移行日を決めません。長文や複数の動きを無理に詰め込まず、原資料は手元に保持してください。

## 保存・確認・将来の変換

- 原文・全文・PDF・ZIP・大量の本文断片はGitHubに置きません（公開・非公開とも）。公式URLと手元の原資料を保持します。
- URLを推測で作りません。会議録は人がブラウザで発言と答弁の位置を確認します。同一発言ブロックから分けたカードだけがURLを共有でき、別ブロックを会議単位のURLで一括上書きしません。
- 会議録検索サイトへの自動アクセスは行いません。自治体の利用条件は[議事録の集め方と保存](議事録の集め方と保存.md)を参照してください。
- AIの整理を原資料と照合し、JSONの妥当性、IDの重複・接頭辞、項目名、null、出典と判定の整合を確認します。JSON Schemaは形式を検査するもので、事実の正しさや議員本人の確定を代行しません。
- `starter-0.x` は暫定仕様です。中核項目はできるだけ維持し、変更時は旧版から新版への変換方法を同時に提供します。機械変換と事実確認は別であり、既存の判定やメモが自動で確認済みになるわけではありません。
- 現行三神DBから移す場合、配列を `records` に包み、版とslugを付け、空文字をnullへ正規化します。ただし既存IDを勝手に付け直したり、旧判定を新判定として扱ったりしません。全項目を移す正式変換ツールは今回の範囲に含みません。
